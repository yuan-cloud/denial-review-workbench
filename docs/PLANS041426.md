## Frozen structural decisions

### Folder structure
Flat case folders. No documents/ subfolder.

CORRECT:
  data/cases/case-002/denial-letter.md
  data/cases/case-002/auth-request.md
  data/cases/case-002/notes.md

WRONG — do not create:
  data/cases/case-002/documents/...

### Init order (must follow exactly)
1. acfs newproj (handles git init and br init)
2. Vite init inside frontend/
3. Then create all other files and folders

### Storage
JSONL first, not SQLite.
Event store path: data/runs/{run_id}.jsonl
Use run_id, not case_id. One case can have multiple runs.
One JSON object per line. Append only. Never rewrite lines.
Migrate to SQLite only if core is solid and time allows.

### Model calls
At most three model calls.

1. extract_facts
2. analyze_gap_or_appeal_basis
3. draft_next_action, only when should_escalate is false

If should_escalate is true, stop after analyze_gap_or_appeal_basis.
Do not call draft_next_action. Everything else is plain code.

### Escalation branch
When findings.should_escalate is true:
- status becomes "escalated"
- draft_next_action is not called
- recommendation field remains null
- approval UI is not shown
- center panel shows escalation notice only
- replay reconstructs escalated state from findings payload

### V1 run status values
approval_requested   — non-escalation path, awaiting human action
approved             — human reviewed and approved the final draft
escalated            — should_escalate was true, no draft generated

Replay does not create a new status. A run that was approved and then
replayed stays approved. Replay responses include is_replay_response: true
as response metadata. This field is never persisted to the JSONL log.

"rejected" is not a v1 status and does not exist anywhere in v1.
Do not add it to the API, event types, UI, or replay logic.

### Replay rule
Replay is read-only reconstruction from persisted events.
It must never call model providers or produce new side effects.
This comment must appear verbatim in replay.py and never be removed:
  # Replay is read-only reconstruction from persisted events.
  # It must never call model providers or produce new side effects.

### Agent Flywheel
Build method only. Not the product label.
Belongs in README, AGENTS.md, and Q&A only.
Never appears in demo, product title, or operator-facing surface.

## Path resolution (CRITICAL — apply to every backend file that touches the filesystem)

uvicorn is started from denial-review-workbench/backend/:
  cd backend && uvicorn app.main:app --reload --port 8000

This sets cwd = denial-review-workbench/backend/. Bare relative paths
like "data/cases/..." resolve to backend/data/cases/... which does not
exist. Every file read crashes with FileNotFoundError.

Add these lines at the top of pipeline.py, policy_search.py,
event_store.py, and main.py:

  from pathlib import Path
  REPO_ROOT = Path(__file__).resolve().parent.parent.parent
  DATA_DIR = REPO_ROOT / "data"

Then use DATA_DIR everywhere:
  case_dir    = DATA_DIR / "cases" / case_id
  policy_path = DATA_DIR / "policies" / f"{facility_id}.md"
  run_path    = DATA_DIR / "runs" / f"{run_id}.jsonl"
  meta_path   = DATA_DIR / "cases" / case_id / "meta.json"

Never use bare string paths. They break whenever cwd is not the repo root.

## Port configuration (CRITICAL — must stay in sync)

Frontend runs on port 5274. This is not the Vite default (5173).
Port 5274 is chosen to avoid conflicts with other local services.

### frontend/vite.config.ts (required)
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  server: {
    port: 5274,
    strictPort: true,   // exit loudly if port is taken; never drift silently
  },
  plugins: [react()],
})

strictPort: true means Vite exits with an error instead of picking
a different port. You discover the conflict at startup, not mid-demo.

### CORS in main.py must match exactly:
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5274"],
    allow_methods=["*"],
    allow_headers=["*"],
)

If these two values ever differ, every browser API call fails with
a CORS error. The UI freezes. The network tab shows the reason but
nothing in the terminal warns you. Keep them in sync.

## Navigation (App.tsx — required before any page component)

No React Router. State-based navigation only.
Two views: case list and run view.
Back button on run view returns to case list without a hard reload.

### frontend/src/App.tsx

import { useState } from "react";
import CaseListPage from "./pages/CaseListPage";
import RunPage from "./pages/RunPage";

type View =
  | { page: "cases" }
  | { page: "run"; caseId: string; runId: string };

export default function App() {
  const [view, setView] = useState<View>({ page: "cases" });

  if (view.page === "cases") {
    return (
      <CaseListPage
        onSelectCase={(caseId: string, runId: string) =>
          setView({ page: "run", caseId, runId })
        }
      />
    );
  }

  return (
    <RunPage
      caseId={view.caseId}
      runId={view.runId}
      onBack={() => setView({ page: "cases" })}
    />
  );
}

### Component prop contracts (must match App.tsx exactly)

CaseListPage props:
  onSelectCase: (caseId: string, runId: string) => void
  Called after POST /runs succeeds. Pass run_id from the response.

RunPage props:
  caseId: string
  runId: string
  onBack: () => void

Never add router imports. Never use window.location. Never hard reload.

### facility-a.md

# Facility A — Prior Authorization Policy

## Skilled Nursing Follow-up

Required documentation for authorization:
- Signed physician order within 30 days of service
- Progress notes within 30 days of service
- Functional assessment if last assessment older than 60 days

Denial appeal basis:
- Missing documents: request specific missing items, then resubmit
- Medical necessity dispute: attach clinical notes with physician
  attestation before filing formal appeal
- Conflicting denial reasons: escalate to compliance review before acting

Approval threshold: all required documents present and dated correctly.

### User message construction (required in pipeline.py)
Each pipeline function calls call_model(system, user). The `user`
argument must be constructed as follows:

extract_facts(documents: list[CaseDocument]) -> CaseFacts:
  user = "\n\n".join(
      f"[{doc.doc_id}]\n{doc.text}"
      for doc in documents
  )

analyze_gap(facts: CaseFacts, policy_sections: list[str],
            documents: list[CaseDocument]) -> CaseFindings:
  # Include original documents so model can quote from them in evidence_refs.
  # The VERBATIM_QUOTE_RULE requires quotes from "provided documents" —
  # without original docs in context, model can only quote from facts JSON.
  doc_text = "\n\n".join(f"[{d.doc_id}]\n{d.text}" for d in documents)
  user = (
      f"ORIGINAL DOCUMENTS:\n{doc_text}\n\n"
      f"EXTRACTED FACTS:\n{json.dumps(facts.model_dump())}\n\n"
      f"POLICY SECTIONS:\n" + "\n---\n".join(policy_sections)
  )

draft_next_action(findings: CaseFindings) -> Recommendation:
  user = f"CASE FINDINGS:\n{json.dumps(findings.model_dump())}"

import json at top of pipeline.py (single import, use json.dumps() everywhere).
Always call model_dump() on Pydantic objects before json.dumps().
Never pass raw Pydantic objects to json.dumps() — it will raise TypeError.

### load_documents — filename to type mapping (required constant)

The mapping from filename stem to CaseDocument type is NOT mechanical.
"notes" → "clinical_notes" is a semantic rename. Any agent deriving
the type by pattern (e.g. replacing hyphens with underscores) will
produce "notes" instead of "clinical_notes" and fail Pydantic validation.

Use this constant exactly:

  FILENAME_TO_TYPE: dict[str, str] = {
      "denial-letter": "denial_letter",
      "auth-request":  "auth_request",
      "notes":         "clinical_notes",   # semantic rename — not derivable by pattern
  }

  def load_documents(case_id: str) -> list[CaseDocument]:
      case_dir = DATA_DIR / "cases" / case_id
      documents = []
      for md_file in sorted(case_dir.glob("*.md")):
          stem = md_file.stem
          if stem not in FILENAME_TO_TYPE:
              logger.warning("skipping unknown document file: %s", md_file.name)
              continue
          doc_type = FILENAME_TO_TYPE[stem]
          text = md_file.read_text(encoding="utf-8").strip()
          documents.append(CaseDocument(doc_id=stem, type=doc_type, text=text))
      return documents

from app.errors import PipelineError  # import from errors.py, not pipeline.py

client = anthropic.Anthropic(timeout=30.0)

def call_model(system: str, user: str) -> str:
    """Single entry point for all model calls. pipeline.py calls only this.
    Swapping providers means rewriting only this function, not pipeline.py."""
    response = client.messages.create(
        model="claude-sonnet-4-6",
        max_tokens=2048,
        system=system,
        messages=[{"role": "user", "content": user}],

        raise PipelineError(
            stage="call_model",
            raw_response=str(response.content),
            cause=ValueError("unexpected response shape from API"),
        )
    return response.content[0].text

## policy_search.py input contract (backend/app/policy_search.py)

def retrieve_policy_sections(
    facility_id: str,
    service_requested: str,
    denial_reason: str,
    required_documents: list[str],
) -> list[str]:

File path: DATA_DIR / "policies" / f"{facility_id}.md"
Read this file and split by "## " headings into sections.
Keyword match on: service_requested, denial_reason, required_documents.
A section matches if any keyword appears (case-insensitive) in it.
Return top 3 matching sections as list of strings.
If zero sections match, return the first 2 sections from the file.
Do not return the full file on zero-match — it floods model context
with irrelevant content and degrades precision at the exact moment
keyword matching has already failed. Policy files lead with their
most general rules, making first sections the safest fallback.
Empty policy context causes hallucinated findings.
Do not build a vector database.
Do not call any model for retrieval.

## Replay spec (backend/app/replay.py)

# Replay is read-only reconstruction from persisted events.
# It must never call model providers or produce new side effects.

Read DATA_DIR / "runs" / f"{run_id}.jsonl" line by line in order.
Parse each line as JSON. Wrap each json.loads() in try/except
json.JSONDecodeError — skip malformed lines with a warning log rather
than raising. A crash mid-append produces a partial line; replay must
survive it.

Rebuild RunStatus by processing events:

  run_started.payload
    -> seed run_id, case_id, facility_id

  documents_loaded.payload.documents
    -> populate documents field

  facts_extracted.payload.facts
    -> populate facts field

  policy_retrieved.payload.retrieved_policy_sections
    -> populate retrieved_policy_sections field

  analysis_completed.payload.findings
    -> populate findings field
    -> if findings.should_escalate is true, set status to "escalated"

  draft_generated.payload.recommendation
    -> populate recommendation field

  approval_requested
    -> no explicit state change; status resolves to "approval_requested"
       by the return logic below if no approved event exists

  approved.payload.final_recommendation
    -> replace recommendation with final_recommendation
    -> set status to "approved"

Resolve final status in a separate function (SRP):

  def resolve_status(state: dict) -> str:
      """state is a plain Python dict during reconstruction.
      All values come from json.loads() — plain types, not Pydantic objects.
      state["findings"] is a dict, so .get() works on it."""
      if state.get("findings", {}).get("should_escalate"):
          return "escalated"
      if state.get("status") == "approved":
          return "approved"
      return "approval_requested"

Set state["status"] = resolve_status(state).
Set state["is_replay_response"] = True.
This field is not persisted to JSONL. It is response metadata only.

Never call pipeline.py functions.
Never call anthropic_client.py.
Never write any new events or files.

### frontend/src/api.ts (required — single source of truth for API calls)
const API_BASE = "http://localhost:8000";

export async function postRun(caseId: string): Promise<RunStatus> {
  const res = await fetch(`${API_BASE}/runs`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ case_id: caseId }),
  });
  if (!res.ok) throw new Error(`POST /runs failed: ${res.status}`);
  return res.json();
}

export async function postApprove(
  runId: string, draftText?: string
): Promise<RunStatus> {
  const res = await fetch(`${API_BASE}/runs/${runId}/approve`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ draft_text: draftText ?? null }),
  });
  if (!res.ok) throw new Error(`POST /approve failed: ${res.status}`);
  return res.json();
}

export async function getReplay(runId: string): Promise<RunStatus> {
  const res = await fetch(`${API_BASE}/runs/${runId}/replay`);
  if (!res.ok) throw new Error(`GET /replay failed: ${res.status}`);
  return res.json();
}

export async function getCases(): Promise<{ case_id: string }[]> {
  const res = await fetch(`${API_BASE}/cases`);
  if (!res.ok) throw new Error(`GET /cases failed: ${res.status}`);
  return res.json();
}

All components import from api.ts. Never write fetch() inline in components.
